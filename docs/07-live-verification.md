# 실제 학생 계정 운영 검증 — 2026-10-04

사용자가 `.env.local`에 제공한 학생 계정 2개로 운영 앱을 검증했다. 계정 이메일·비밀번호·토큰·signed URL은 문서와 저장소에 기록하지 않는다.

## 로그인·저장·계정 격리

- 두 계정 모두 이메일·비밀번호 브라우저 로그인 및 서버 `student` 역할 확인.
- 각 계정이 생성한 시험 프로젝트를 다른 계정이 조회·삭제·업로드하는 요청은 모두 HTTP 403. 목록에도 노출되지 않음.
- 사용자 JWT로 직접 PostgREST RLS 조회: 본인 프로젝트 1행, 다른 학생 0행.
- 텍스트 저장, 오래된 revision 저장 거부(HTTP 400), 새로고침 후 유지.
- 비공개 Storage signed 이미지 업로드·저장·signed 다운로드, 새 브라우저 로그인 후 텍스트/이미지 재조회 통과.
- 로그아웃 후 로그인 화면 복귀 확인.

Storage SDK의 `info()`는 최상위 `size`를 반환하는데 서버가 `metadata.size`를 읽어 이미지를 저장하지 못했다. 최상위 값 검증으로 수정했으며 위조 크기·누락 크기·타 사용자 경로 거절 회귀 테스트를 추가했다.

## 실제 AI

초기 요청은 턴 상한 10 USD 전체를 예약해 일일 예산보다 커져 공급자 호출 전에 차단됐다. 최대 토큰/단계·문맥을 고려한 보수적 예상액을 예약하도록 수정했다. 상한·일/월 예산은 올리지 않았다. 비동기 오류가 빈 HTTP 500으로 전달되던 문제도 수정했다.

`qwen/qwen3.8-flash` 실제 요청은 OpenRouter가 ZDR 조건을 지원하는 엔드포인트가 없다는 HTTP 404로 거부했다. 데이터 보호 설정은 유지했다. 해당 실패의 앱 사용량에는 보수적 예약액 $0.0510488이 기록되어 있다. **이 값은 공급자 실청구 확정액이 아니다.** 공급자 대사 전 임의로 0원으로 덮어쓰지 않았다. 추후 관리자 과금 대사 대상이다. 해당 generation 조회도 HTTP 404로 기록이 없어 공급자 최종 청구액은 확인하지 못했다.

등록된 `google/gemini-3.1-flash-lite`로 실제 요청을 실행했다.

- 완료 약 9.4초, `read_file` → `write_file`, 승인 대기 제안 1개.
- 승인 전 원본 파일 유지, 다른 계정의 승인 HTTP 403, 본인 승인 후 CSS 저장.
- 입력 2,644 / 출력 334 토큰, 앱 계산 비용 $0.001162, 미정산 예약 증가 0.
- 사용자 선택에 따라 로컬·Vercel Production `OPENROUTER_MODEL_CODE`를 위 모델로 변경.
- 모델 가격 조회에서 ZDR 가능한 모델만 허용하고, SDK 기본 오류 로그의 요청 본문 출력을 차단했다.

ZDR 지원은 [OpenRouter 공식 목록](https://openrouter.ai/docs/api/api-reference/endpoints/list-endpoints-zdr)과 실제 요청으로 확인했다. 앱 토큰 단가 계산은 공급자 최종 청구 대사를 대체하지 않는다. 비전 입력·이미지 생성 호출은 이번 검증에 포함하지 않았으며 이미지 생성 플래그는 계속 꺼져 있다.

## 라운지 연동

라운지 `94eeabc1`에 내부 HMAC API와 기존 배포 코어 연결, DB nonce, 업로드 크기/SHA 검증, 완료 receipt, 비공개 작품의 일회용 owner launch를 반영했다. DB 원장은 기존 라운지 migration을 사용한다. 에디터의 동일 ZIP은 파일 정렬과 고정 ZIP 시각으로 같은 SHA를 유지한다.

운영 학생 계정으로 첫 비공개 배포, 같은 prepare 요청의 작품/업로드 ID 재사용, signed ZIP 업로드, complete 완료 receipt 재사용, 썸네일/비공개/목록 숨김 저장, 서명 없는 요청 401, 다른 학생 소유권 403, nonce 재사용 409, owner Play 실행을 확인했다.

에디터 Production과 로컬 `EDITOR_DEPLOY_ENABLED=true`로 활성화했다. 두 번째 학생의 실제 브라우저 화면에서 다음을 추가 검증했다.

- 첫 배포 후 수정·재배포가 같은 라운지 작품 ID를 유지하고 ZIP SHA가 변경됨.
- 새로고침 후 설명·slug·비공개·목록 숨김 설정 유지.
- 변경 없는 재시도는 동일 SHA와 기존 결과 URL/완료 receipt 재사용.
- 다른 학생의 `launch` 요청 HTTP 403.
- 에디터 ‘작품 열기’ 팝업에서 Play 303 → 200, 수정 내용 표시, URL의 일회용 코드 제거, `window.opener === null` 확인.
- 익명 브라우저의 비공개 작품 접근 HTTP 403.

첫 UI 팝업 검사에는 60초 대기 초과가 한 번 발생했다. 서버 저장 내용과 Play HTTP 200/수정 내용을 직접 대조하고, 새 owner launch로 동일 버튼을 다시 실행해 통과했다. 원인은 확정하지 않았으며 파일럿에서 시작 지연을 관찰한다. 시험 프로젝트와 라운지 시험 작품은 검토용으로 남겨 두었고 라운지 작품은 모두 비공개·목록 숨김이다.
