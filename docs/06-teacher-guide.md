# 선생님 안내 — 에디터 확인 순서

메인 화면에는 나의 프로젝트 목록이 표시된다. 새 프로젝트는 이름만 입력해 만들며, 기본 HTML·빈 CSS·빈 JavaScript와 프로젝트 기록인 `PROJECT.md`로 시작한다. 프로젝트를 선택하면 파일 탐색기·미리보기·LECO (레코)가 열린다. 파일을 클릭하면 코드 편집으로 전환하고, 대화 선택에서 세션을 바꾼다. 선택한 대화는 오른쪽 휴지통으로 삭제하며 프로젝트 파일은 유지된다. 왼쪽 위 로고를 누르면 저장 후 목록으로 돌아간다. 저장에 실패하면 작업 화면을 유지한다.

학생이 만들거나 수정할 내용을 요청하면 AI가 파일을 생성·수정하고, 정상 완료한 작업을 한 번에 저장한 뒤 미리보기를 연다. 여러 파일은 같은 버전으로 반영하며 실패·중단된 응답과 수동 편집으로 오래된 변경안은 자동 반영하지 않는다. 삭제·이름 변경은 개별 확인한다. 배포 창에서 제목·설명·분류·주소·공개 여부를 입력하면 같은 라운지 작품을 갱신한다. 계정 연결 전 로컬 데모의 “배포”는 ZIP 정책 검사만 수행한다.

새 대화에서도 프로젝트 문서를 먼저 읽고, 필요한 코드만 읽는다. 덮어쓸 기존 파일을 끝까지 읽지 않으면 변경을 차단한다. 코드 생성·수정 시 작품 목적·기능·규칙·파일 역할·실행 방법·변경 기록이 담긴 `PROJECT.md`도 함께 갱신한다. 기존 프로젝트에 문서가 없으면 다음 AI 코드 작업에서 생성한다. 채팅에는 코드 대신 작성 중 표시와 짧은 결과 설명을 보여준다.

1. 상단 저장 상태를 확인한다. 변경 내용은 1분마다 자동 저장되고, 다른 탭으로 이동하거나 창을 내리면 바로 저장된다. “저장 대기”가 보이는 상태에서 수업을 마치거나 탭을 닫을 때는 Ctrl+S(Mac은 ⌘+S)로 먼저 저장한다. 오류면 저장 다시 시도 후 ZIP을 보관한다.
2. 다른 탭 경고가 뜨면 한 탭에서만 편집한다. 충돌 오류는 프로젝트를 다시 열어 최신 파일을 확인한다.
3. 미리보기가 안 뜨면 root `index.html`과 상대 경로를 확인한다. 콘솔을 펼치고 오류 위치를 눌러 파일로 이동한다. TS/React는 정적 JS로 변환해야 배포할 수 있다.
4. AI가 안 되면 편집과 저장은 계속 진행한다. 예산·모델·계정 상태는 관리자에게 확인한다. 삭제·이름 변경은 자동 적용에서도 학생이 승인한다.
5. 배포 오류는 금지 파일, 확장자, 루트 절대 경로, 크기 제한 순으로 확인한다. 연결된 작품이 삭제되었으면 연결 해제 후 새 작품으로 배포한다.
6. DB 연결(상단 **DB**)은 학생 본인 Supabase 프로젝트의 Project URL과 anon key만 사용한다. service_role·secret 키는 입력 단계에서 막히며, 파일에 들어 있으면 배포가 차단된다. 연결 후 **코드에 넣기**로 `supabase.js`를 만들고, **테이블 만들기 SQL 복사**로 RLS가 켜진 방명록 테이블을 Supabase SQL Editor에서 만든다. RLS가 꺼진 테이블은 누구나 읽고 쓸 수 있다. 미리보기는 연결한 프로젝트 주소로만 요청할 수 있고, **연결 해제**하면 다시 모두 차단된다.
7. 배포 결과가 불확실하면 연속 재배포하지 않는다. 관리자가 내부 업로드 receipt, lease와 Storage 상태를 확인한다. 비공개 작품은 라운지에서 로그인 후 연다.

학생 코드·채팅·이미지나 키를 공개 이슈에 붙이지 않는다. 문제 보고에는 재현 단계, 프로젝트/스레드 ID, 시각, 오류 종류만 적는다. 개인정보 처리방침과 보호자 동의 검토가 끝난 뒤 실제 학생 AI 사용을 시작한다.

## 로그인

라운지에서 사용하던 이메일과 비밀번호를 입력하고 **이메일로 로그인**을 누른다. 비밀번호가 없거나 기억나지 않으면 **이메일 로그인 링크 이용하기** 또는 **카카오로 로그인**을 선택한다. 로그인은 기존 라운지 계정을 사용하며, 활동 중인 계정만 편집기에 접근할 수 있다.

## 개인 저장공간

프로젝트 하나당 30MB, 계정당 현재 프로젝트 파일을 합산해 100MB까지 저장합니다. 프로젝트 목록 상단에서 사용량과 전체 한도를 확인합니다. 프로젝트 복사본도 용량에 포함되며, 삭제한 프로젝트·이전 파일 버전·AI 첨부는 표시 용량에서 제외합니다. 저장 및 프로젝트 파일 업로드 요청에서 한도를 검사하고, 초과 시 기존 파일을 유지한 채 오류를 표시합니다.

현재 서버 검사는 저장 전 조회 방식입니다. 서로 다른 프로젝트를 동시에 저장하는 경우까지 엄격하게 한도를 보장하려면 라운지 소유 저장 RPC에 계정 잠금을 추가해야 합니다. 이 변경은 공유 DB migration을 적용하지 않습니다.

## AI 사용량 표시와 코딩 모델

LECO 상단은 `25% 남음 (20일 후 초기화)` 형식으로 월간 한도에서 사용·예약 금액을 제외한 비율을 표시합니다. 한국 시간 매월 1일에 초기화하며 일일 제한은 서버에서 별도로 검사합니다.

2026-10-07 초기 로컬 코딩 모델을 `openai/gpt-6-luna`로 변경했습니다. 기존 OpenRouter Chat Completions 연동에서는 도구 호출 호환을 위해 추론 수준 `none`을 명시합니다. 추론과 도구를 함께 사용하려면 Responses 연동이 필요합니다. ZDR·예약·계정별 예산 검사는 유지합니다. 운영 환경 모델은 이 변경으로 배포하지 않았으며, 실제 게임 생성 품질을 비교하는 유료 호출은 수행하지 않았습니다.

공개 단가는 입력 100만 토큰 $0.10, 출력 $0.50입니다. 예를 들어 한 요청 전체 입력 10,000·출력 3,000토큰, 3,000명이 월 30회씩 사용하면 기본 토큰 비용은 약 $225입니다. 단계별 반복 문맥·추론·캐시·이미지 및 OpenRouter 결제 수수료는 별도이며 실제 사용량으로 확인해야 합니다. 계정별 월 $2 한도를 3,000명이 모두 사용하면 총 $6,000까지 발생할 수 있습니다. 참고: https://developers.openai.com/api/docs/models/gpt-6-luna


2026-10-07 루나 스네이크 생성 실패를 시험 계정에서 재현했습니다. 기존 4,096토큰 한도에서는 파일 입력 오류로 실패했고, 8,192토큰으로 늘린 재검증에서는 네 파일이 38초에 생성됐습니다. 생성 파일의 반영, sandbox 미리보기의 캔버스와 콘솔 오류 0개, 홈 재진입을 확인했습니다. 이후 고정 출력 한도는 제거하고 공식 모델 최대 출력량과 계정의 남은 일/월 예산, 요청당 예산 중 작은 범위에 맞춰 출력량을 계산합니다. 반복 단계에 재사용되는 입력도 예약 예상액에 포함합니다.

로컬 `EDITOR_AI_MAX_TURN_USD`는 사용자 요청으로 일일 한도와 같게 맞췄습니다. 월간 한도는 그대로 검사하며 예상 최대 비용을 먼저 예약하고 실제 사용량으로 정산합니다. 예산 부족은 유료 호출 전에 차단합니다. 실패·중단·출력 한도 초과는 빈 답변 대신 안내를 표시하며 해당 변경을 자동 반영하지 않습니다. 작성 글자 수는 도구 입력 JSON을 포함한 대략적인 수치입니다.


2026-10-07 사용자 요청으로 로컬 코딩 모델을 `qwen/qwen3-coder-next`로 전환했습니다. 기존 프롬프트, PROJECT.md 우선 읽기, 부분 수정 우선, 전체 교체 승인, 금지 주제 거절, ZDR와 계정별 예산 검사를 유지합니다. 이미지 첨부용 모델은 별도 설정을 유지합니다. 운영 환경은 배포하지 않았습니다. 모델 참고: https://huggingface.co/Qwen/Qwen3-Coder-Next

2026-10-07 Qwen 시험 후 사용자 요청으로 로컬 코딩 모델을 `deepseek/deepseek-v4.1-flash`로 전환했습니다. OpenRouter 공개 ZDR 목록의 도구 호출 지원을 확인했고, 기존 프롬프트·파일 변경 보호·예산·이미지 첨부용 모델 설정을 유지했습니다. 시험 계정의 새 스네이크 프로젝트에서 파일 4개를 15초에 제안했으며 도구 오류는 없었습니다. 세밀한 수정 품질 비교와 운영 배포는 수행하지 않았습니다. 참고: https://openrouter.ai/deepseek/deepseek-v4.1-flash

응답 종료 후 백그라운드 작업은 없습니다. 모델이 파일 변경안 없이 구현 완료나 계속 작업 중이라고 주장하는 명시적 표현은 서버에서 실패 안내로 교체합니다. 표현 기반 검사는 의미 전체를 판별하지 않으며, 실제 모델의 작업 품질 검증을 대체하지 않습니다.

작성량 표시는 0자부터 시작하며 준비·응답 텍스트와 파일 도구 입력을 합산한 대략적인 글자 수입니다. 준비 내용 자체는 전송하지 않습니다. 도구 입력이 스트리밍되지 않고 한 번에 도착하면 최종 입력 크기로 보완합니다. 순수 코드 길이나 토큰 사용량과는 다릅니다.
